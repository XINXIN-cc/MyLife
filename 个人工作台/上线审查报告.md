# 个人工作台上线审查报告

审查日期：2026-08-02

## 当前结论

**暂缓公开上线，完成下列“必须项”后可以先小范围试用。**

页面结构、主要交互和本机保存功能已具备测试条件，但云端连接尚未配置。当前直接发布后，用户会停留在登录页，无法完成注册或登录。

## 上线前必须完成

1. 在 `cloud-config.js` 填入 Supabase Project URL 与公开 anon key。严禁填写 `service_role` 密钥。
2. 在 Supabase SQL Editor 执行 `supabase-setup.sql`，确认数据表已建立并启用 RLS 用户隔离。
3. 在 Supabase Authentication → URL Configuration 中填写正式站点地址，并将正式站点加入 Redirect URLs，否则找回密码链接无法正确返回。
4. 在发布页提供一个真实有效的联系邮箱或反馈入口，用于账号删除、数据删除和隐私问题。
5. 使用真实手机、iPad 和电脑各测试一次：注册、登录、刷新后保持登录、退出、忘记密码、推送云端、从云端拉取、删除记录、导出备份。

## 已通过的静态检查

- JavaScript 语法检查通过。
- HTML 未发现重复 `id`。
- 未发现残留的内联 `onclick` 事件。
- 本地脚本、样式、协议和隐私页面引用完整。
- 已添加 Vercel 安全响应头，包括 CSP、禁止嵌入、类型嗅探保护与权限限制。
- 密码由 Supabase Auth 处理，工作台不保存明文密码。
- 云端记录按用户 ID 隔离，本机记录也按账号区分。
- 支持令牌刷新、退出登录、忘记密码和重设密码流程。
- 页面具备手机、平板和电脑响应式布局。

## 已知限制

- 云同步是手动整份数据推送/拉取，多设备同时修改时属于“后保存覆盖先保存”，暂时没有逐条合并和冲突提示。
- 上传的图片和视频只存在当前浏览器，不会同步到其他设备；清理浏览器数据可能丢失，需定期备份。
- 健康、热量、饮水及训练数据仅供记录，不能作为医疗建议。
- 项目由较大的单页 HTML/CSS/JS 文件组成，可以运行，但后期继续增加功能时应拆分模块以降低维护风险。
- 当前没有自动化端到端测试；每次大更新发布前仍需要回归测试关键流程。

## 建议的上线方式

先邀请 3–5 人试用 7 天，重点观察登录失败、数据丢失、移动端遮挡、视频播放和多设备覆盖问题。确认无严重问题后再公开推广。

每次更新代码并重新部署后，网页版用户通常会在下次刷新时获得新版本；若后续做成可安装 PWA，需要另行处理缓存更新提示。
