# 个人工作台上线审查报告

审查日期：2026-08-02

## 结论

当前版本适合继续个人试用和小范围内测，但还不建议直接作为公开、多用户正式产品上线。

原因不是页面无法使用，而是当前仍是单文件前端应用：代码体积较大、媒体文件主要保存在浏览器、缺少正式部署域名、自动化回归测试和云端媒体同步。

## 已通过

- JavaScript 语法检查通过。
- HTML 元素 ID 无重复。
- 核心页面在手机、iPad、电脑均有响应式规则。
- 任务、目标、喝水、运动、饮食、阅读、专注、课程、日记等核心记录均可本地保存。
- 导入数据前会自动导出恢复前备份。
- 用户文本进入动态 HTML 前大部分已做转义。
- 视频链接限制为 HTTP/HTTPS，降低危险协议风险。
- 增加键盘焦点样式和减少动态效果偏好支持。
- 英语每日完成状态已改为按日期保存。
- 旧版阅读日期会转换为统一日期格式。

## 本轮新增的多人方案

- 设置页新增 Supabase 项目连接、注册、登录、上传和下载。
- 每个账号使用独立 `user_id` 数据行。
- 提供 Row Level Security 策略，用户只能读写自己的数据。
- 登录令牌过期后会尝试自动续期。
- 同一浏览器切换账号时使用独立本地缓存，避免直接看到上一个账号的数据。
- 云同步失败时仍可继续使用本地模式。

建表脚本：`supabase-setup.sql`

## 当前数据保存方式

- 文字、任务和统计：localStorage。
- 本地图片和视频：IndexedDB。
- 手动导出：JSON 文件，仅包含文字记录和设置。
- 云同步：当前只同步 JSON 文字记录，不同步大图片和视频。

## 上线前仍需完成

### 必须

1. 将页面部署到 HTTPS 域名，不能继续使用 `file://` 作为正式入口。
2. 创建 Supabase 项目并执行 `supabase-setup.sql`。
3. 在设置页填写 Project URL 和 publishable/anon key，测试注册、登录、上传和下载。
4. 对真实手机、iPad、Windows 和至少一种 Android 浏览器进行人工回归测试。
5. 增加隐私说明、数据删除说明和用户协议。
6. 决定图片和视频是否需要跨设备同步；如需要，应接 Supabase Storage，并设置文件大小与空间配额。

### 建议

1. 将 `app.js` 按功能拆分，避免单文件继续膨胀。
2. 将 `style.css` 拆为基础、组件和响应式样式。
3. 增加自动保存状态、云端最后同步时间和冲突提示。
4. 加入 PWA manifest、应用图标和离线缓存。
5. 将过小的 7px～9px 辅助文字逐步提升至手机可读尺寸。
6. 为删除、覆盖、清空等操作增加统一确认弹层。

## 多人使用边界

- 不同账号：数据可以隔离。
- 同一账号多设备：可以手动上传、下载，当前采用整份数据覆盖，不自动合并。
- 多人共同编辑一份数据：尚未实现，需要增加家庭/小组空间、成员表和共享权限。
- 本地视频：当前不跨设备，不包含在 JSON 备份内。

## 推荐上线顺序

1. 先以个人账号完成 Supabase 连接测试。
2. 用两个测试邮箱验证数据隔离。
3. 部署到 HTTPS 测试域名。
4. 邀请 2～5 人内测一周。
5. 修复内测问题后，再决定是否接云端媒体和共享空间。
